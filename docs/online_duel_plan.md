# 1:1 온라인 대전 — 설계·진행 노트

친구와 브라우저끼리 연결해 캐시(또는 다니엘)로 1:1 결투를 하는 기능의 설계 노트입니다. 큰 작업이라 단계별로 나눠 진행합니다.

## 방식: 호스트 판정 + 명령 전송

| 방식 | 내용 | 판단 |
|---|---|---|
| **호스트 판정 (채택 예정)** | 방을 만든 쪽(호스트)이 게임을 실제로 계산. 손님은 입력 명령만 보내고, 호스트가 보내 주는 상태(스냅샷)를 그림. 손님 쪽 내 캐릭터 이동은 미리 움직여 보여 줌(예측) | 브라우저·PC가 달라도 결과가 어긋나지 않음. 호스트가 약간 유리(지연 0) |
| 락스텝(서로 입력만 교환) | 둘 다 같은 계산을 하고 입력만 주고받음 | 통신량은 가장 적음. 하지만 브라우저마다 `Math.sin` 등의 미세한 차이로 결과가 갈라질 위험이 있고, 지연만큼 입력이 늦게 반응함 |

결정적인 시뮬레이션(아래 1단계)은 어느 방식이든 도움이 됩니다. 호스트 방식에서는 동기 어긋남을 디버깅하고 리플레이를 만드는 데 씁니다.

## 단계

### 1단계: 준비 (완료)
- **명령 계층** `src/6_a_cmd.js`
  - 키·마우스 입력을 `{ k: 틱, t: 종류, x, y, id, s }` 명령으로 바꿔 한 곳(`Cmd.apply`)에서 적용합니다.
  - 상대의 입력도 같은 형식으로 받을 수 있습니다.
  - 명령은 기록(`Cmd.log`)과 재생(`Cmd.replay`)이 됩니다. `Cmd.record()`는 한 판을 다시 만드는 데 필요한 정보 전체를 돌려주고, `Cmd.hash()`는 상태 요약값을 돌려줍니다.
- **시드 난수** `Rng` / `rnd()` / `rand()`
  - 치명타, AI 판단, 소음 위치, 회피 패턴, 스피어 이동 지점처럼 결과에 영향을 주는 곳만 시드 난수를 씁니다.
  - 화면 효과와 소리는 `Math.random` / `vrand()`를 씁니다.
  - `Game.start`마다 새 시드를 정하고, `opts.seed`로 지정할 수도 있습니다.
- **틱 카운터** `Game.tick`, 판 시작 기준 유닛 id `Game.uid0`
- **선입력 버퍼를 게임 시간 기준으로**: 예전에는 실제 시계 기준이라 게임 속도 0.7x에서 판정이 달라졌습니다.
- **2D 그리기가 판정 난수를 소모하던 문제 수정**: 화면을 켜고 끄는 것만으로 결과가 달라지던 문제입니다.
- **다니엘 걸작(R) 탈출 방향**: 실시간 커서를 직접 읽던 것을 명령에 담긴 좌표(`cur` 명령)로 바꿨습니다.
- **팀에 상관없는 판정** (상대도 사람이 조종하는 캐시일 수 있게)
  - `Game.enemies / visibleEnemies / nearestEnemy / pickEnemyAt`가 기준 유닛을 인자로 받습니다. 기본값은 내 캐릭터입니다.
  - 캐시 투사체 팀을 시전자 팀으로 바꿨습니다(전에는 0으로 고정).
  - 팀 1의 유도 투사체가 벽을 무시하는 규칙은 AI에게만 적용합니다.
  - 패시브(외상·치명적 외상·출혈)를 공격한 캐시 기준으로 계산합니다.
  - 통계·실수 기록은 `unit.S`를 거칩니다. 내 캐릭터만 실제 `Stats`에 기록되고, 다른 유닛은 `NullStats`로 버려집니다.
- **회귀 테스트**
  - 같은 시드와 같은 명령이면 같은 결과가 나옵니다(캐시와 다니엘, 걸작 커서 포함). 시드가 다르면 결과가 달라지는 것도 확인해서 검사가 유효함을 보였습니다.
  - 2D·3D 그리기는 판정 난수를 쓰지 않습니다.
  - 팀 1 캐시를 명령으로 조종하면 나를 맞히고, 자기 편은 맞히지 않고, 외상은 그 캐시 기준으로 쌓이고, 내 통계에는 섞이지 않습니다.

### 2단계: 상태 전송 + 로컬 연결 시험 (완료)
- **상태 스냅샷** `src/6_b_snap.js`
  - 손님은 같은 옵션·시드로 판을 시작한 뒤 상태값만 덮어씁니다. 설정 객체는 경로(`$s`)로, 유닛 참조는 id(`$u`)로 보내고, 새 유닛과 투사체는 클래스 이름으로 다시 만듭니다. 같은 객체는 재사용합니다.
  - **델타**(`Snap.diff/patch`): 바뀐 값만 보내고 숫자는 소수점 4자리로 줄입니다. 전체 7.5KB가 평균 0.7KB가 되어, 초당 20번 보내도 약 14KB/s(키프레임 포함 약 18KB/s)입니다. 델타 1,199개를 이어 붙인 결과가 전체 스냅샷과 정확히 같습니다.
- **통신** `src/6_c_net.js`
  - 호스트: 6스텝(0.05초)마다 `{ n, base, d(델타) | key(전체), ev(효과·소리) }`를 보냅니다. 2초마다 키프레임을 보냅니다. 손님 명령은 검사(종류·숫자·스킬 키) 후 다음 스텝 시작에 적용합니다.
  - 손님: 계산하지 않습니다. 델타의 기준(`base`)이 맞지 않으면 키프레임을 요청합니다. 위치는 0.05초 동안 부드럽게 보간합니다. 내 입력은 `Cmd`를 거쳐 호스트로 갑니다.
  - 효과·소리 전달: FX(글자·베기·궤적·파티클)와 Sfx를 감싸 호스트에서 일어난 것을 이벤트로 보냅니다. 안쪽 호출은 한 번만 기록합니다.
  - 시점 구분
    - `Sfx.playFor(u, 내 소리, 위치, 남의 소리)`: 맞은 소리, 쓰러지는 소리와 처치음, 오류음, 라운드 승패음을 각자 시점에 맞게 냅니다.
    - `FX.toastFor(u)`: 그 캐릭터의 주인에게만 보이는 알림
    - `FX.toastAll`: 모두에게 보이는 알림(스피어, 낮밤)
    - 실수 알림(`Stats.mistake`)은 전달하지 않습니다.
  - 화면 색(내 편·적)은 `myTeam()` 기준입니다. 손님은 팀 1입니다. 시점이 바뀌면 3D 메시를 다시 만듭니다.
  - 온라인 대전 중에는 일시정지가 막히고 항상 1배속입니다. 호스트가 「다시 하기」를 누르면 판 정보를 다시 보내 손님도 새 판으로 갑니다.
- **대전 모드** `src/5_y_pvp.js` (`Modes.pvp`): 결투의 라운드·점수·스피어 규칙에 상대만 명령으로 조종하는 캐시(팀 1)입니다. 손님 화면에서는 점수와 승패를 뒤집어 보여 줍니다. 손님에게는 경기 종료 화면이 따로 있습니다.
- **실험실** `src/7_a_netlab.js`
  - `cathy_trainer.html?netlab`: 호스트·손님 두 창을 띄우고, 지연·흔들림·손실(재전송 지연)을 넣어 중계합니다. 손님 창을 클릭해서 직접 조종할 수 있습니다.
  - `?netlab&test`: 자동 시험 13개 — 판 정보 수신, 손님 시점, 손님 명령 실행, 같은 시점 상태 일치(81/81), 효과 전달, 맞은 소리, 오류음 분리, 전송량, 빠진 델타 복구, 잘못된 명령 거부, 경기 종료 전달, 다시 하기, 오류 없음. 결과는 제목(NETLAB PASS n)에 나옵니다.
- **알려진 한계** (다음 단계에서 다룸)
  - 손님 입력에는 왕복 지연만큼 반응이 늦습니다. 내 캐릭터 이동을 미리 움직여 보이는 예측은 아직 없습니다.
  - 손님 쪽 통계·코칭이 비어 있습니다. 호스트가 손님용 적중·실수를 따로 보내야 합니다.
  - 카메라(와드) 색, 휴식 글자 등 일부 표시가 호스트 시점입니다.
  - 다니엘은 대전 모드에 아직 없습니다(캐시 대 캐시만).

### 3단계: 대전 모드 다듬기 (완료)
- **손님 이동 예측** (`Net.predictPos`, 설정 「온라인 대전: 내 캐릭터 이동 예측」, 기본 켬)
  - 이동·공격 이동 명령을 보내면, 마지막 호스트 위치에서 목표 쪽으로 「왕복 지연(핑으로 측정) + 받은 뒤 지난 시간」만큼 미리 움직여 보여 줍니다. 벽에서 멈춥니다.
  - 기절·속박·강제 이동·휴식·정신집중 중에는 예측하지 않습니다. 화면 위치는 예측 위치로 부드럽게 따라가고, 1.5m 넘게 어긋나면(점멸·넉백) 바로 맞춥니다.
  - 화면 표시만 바뀌고 판정은 그대로 호스트가 합니다.
  - 측정(지연 80ms·흔들림 30ms): 내 화면 반응이 예측을 끄면 280ms, 켜면 16ms입니다. 멈춘 뒤 호스트 위치와의 오차는 0.000m입니다.
- **손님 통계·코칭**
  - 호스트가 손님 캐릭터 전용 통계(`Stats.make`, `unit.rstats` 숨김 속성)를 따로 기록합니다. 피해·받은 피해·처치·치명적 외상도 캐릭터별(`unit.S`)로 셉니다.
  - 라운드가 끝날 때마다 손님에게 보냅니다(`t:'stats'`). 손님의 라운드 요약 패널과 종료 화면(라운드 표 + 코칭 + 연습 바로가기)에 쓰입니다.
  - 손님의 실수 알림은 손님에게만 가고, 연속 명중 이벤트는 호스트에서 울리지 않습니다. 쿨 낭비 판정도 그 캐릭터 기준으로 바뀌었습니다.
- **시점 표시 정리**
  - `FX.textFor(u, …, 'owner'|'seen'|'all')`, `FX.ringFor`, 색 `'team'`(보는 사람 기준 내 편 파랑·적 빨강)을 추가했습니다. 휴식 글자, 카메라·드론 글자와 링에 적용했습니다.
  - 카메라(와드) 색은 저장하지 않고 그릴 때 보는 사람 기준으로 계산합니다.
  - 피격 시 위치 노출 규칙을 사람이 조종하는 캐릭터 모두에게 적용합니다(대전 양쪽 공정).
- **실험실 자동 시험 20개**: 3단계 항목(예측 반응·복귀·끄기, 시점 색, 손님 통계 도착, 호스트 통계 분리, 종료 화면 코칭) 추가. 3번 반복해도 모두 통과합니다.
- **남은 한계**
  - 평타 대상 지정과 스킬은 예측하지 않습니다(호스트 결과를 기다립니다).
  - 다니엘은 대전 모드에 아직 없습니다.

### 4단계: 실제 연결 (WebRTC DataChannel)
- 브라우저끼리 직접 연결합니다. 게임 데이터는 서버를 거치지 않습니다.
- 다만 **처음 연결할 때 서로의 접속 정보를 교환하는 수단(시그널링)이 필요합니다.** 아래 "정해야 할 것"을 참고하세요.

### 5단계: 다듬기
- 연결 끊김과 재접속, 재대결, 지연 표시(ping)
- 호스트 유리함을 줄이는 지연 보정(되감기 판정은 선택 사항)
- 대전 리플레이 저장(`Cmd.record` 활용)

## 정해야 할 것 (사용자 결정)
> 2026-10-06 결정: **천천히, 무료로, 안정성 우선.** 연결 방법은 **(가) 연결 코드 복사·붙여넣기**(외부 중계 서비스 없음)로 하고, STUN은 무료 공개 서버를 **설정에서 켜고 끌 수 있게** 합니다. 범위와 공개 여부는 아직 정하지 않았습니다.

1. **연결 방법(시그널링)**
   - (가) **연결 코드 복사·붙여넣기**: 서버가 전혀 없습니다. 호스트가 만든 코드를 메신저로 보내고 답 코드를 받아 붙여넣습니다. 번거롭지만 외부 서비스를 쓰지 않습니다.
   - (나) **무료 공개 중계 서비스**(PeerJS 공용 서버 등): 방 번호만 알려 주면 됩니다. 대신 접속 정보가 제3자 서버를 거칩니다.
   - (다) **직접 만든 작은 중계 서버**(Cloudflare Workers 등): 가장 편하지만 사용자 계정과 배포가 필요합니다.
2. **STUN 서버**: 공유기 뒤에서 서로를 찾을 때 공개 STUN(구글 등)을 쓰면 IP 주소가 그 서버에 전달됩니다.
   - TURN(중계)이 없으면 일부 네트워크(회사망, 일부 모바일 데이터)에서는 연결이 안 될 수 있습니다.
3. **범위**: 처음에는 캐시 대 캐시만 할지, 다니엘까지 포함할지
4. **IP 정책 확인**: 온라인 대전은 "연습 도구"보다 "게임"에 가까워집니다. 님블뉴런 문의 결과(`docs/ip_policy_notes.md`)를 보고 공개 여부를 정하는 것이 안전합니다. 개발은 로컬에서 먼저 진행해도 됩니다.
